## 根因归类

1. 旧系统缺少生产体系固定月休 4 天应出勤口径
   - 旧系统只有行政体系 `23天` 行政单双休月历和生产体系 `0应出勤` 分支。
   - Excel 中一批 `affiliation_system=2` 人员使用 `25天 * 8 = 200h`，来源是生产体系固定月休 4 天并结合当月业务公休/假期，而不是行政单双休月历。
   - 本轮已补齐生产体系默认公式：`当月自然天数 - 固定月休4天 - 当月工作日法定休息日`；月历日明细缺失时才回退 `legalHolidayRestDays`。

2. 审批快照时长缺失
   - 多条 `tbattendanceapprove` 记录 `duration/durationUnit` 为空。
   - 统计服务按 `beginTime/endTime` 自然时长兜底，遇到跨夜、秒级时间或包含休息时间的请假会与 Excel 人工小时不一致。

3. 重复审批参与统计
   - 林艳同日同类审批存在近似重复，系统按规则全部累加，Excel 只计一条。

4. 员工或审批映射缺失
   - `hr_0003` 存在多个王芳，必须按员工 ID、工号、部门、手机号匹配；不能按姓名匹配。
   - 王芳（行政人力资源部）与生产部王芳的本地钉钉 ID 对调，导致审批抓取把生产部 13 条调休误挂到行政人力资源部王芳。
   - 多名生产体系人员的 Excel 请假数据在本地审批快照中不存在或未正确解析。

## 解决方案

### 立即处理
- 通过“审批数据”页面修正时长，或重抓审批数据后确认 `duration/durationUnit` 已正确落库。
- 对明确重复的审批行使用“取消至统计”，不要删除原始快照。
- 对 2026-06 目标员工执行“单人统计”或对目标月份执行“开始统计”重算。

### 系统改造
- 已新增生产体系默认出勤日历口径，当前支持：
  - 行政双/单双休 23 天月历；
  - 生产体系固定月休 4 天；
  - 当月落在工作日的业务公休/法定假期配置；
  - 生产体系不得继续写 `0` 应出勤。
- 已调整生产体系实际出勤加班来源：生产体系和行政体系一样只把本地已通过加班审批计入实际/应计出勤公式，月度自动加班只作为加班汇总展示。
- 后续如需要更细规则，再扩展为按员工、岗位或部门配置出勤日历。
- 员工匹配和审批匹配必须使用 `employeeId -> tbattendanceuser.userId -> tbattendanceapprove.userId`，导入/对账时也应优先使用工号、手机号、部门辅助区分同名员工。
- 对 `duration/durationUnit` 为空的请假审批增加异常提示，不应静默使用明显不可靠的自然跨度作为最终扣减。
- 增加同员工、同日期、同类型、近似相同时段审批重复检测，统计前提示或自动排除已标记重复项。
