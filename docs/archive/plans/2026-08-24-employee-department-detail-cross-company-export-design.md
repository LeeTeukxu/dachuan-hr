# 员工部门明细跨公司加密导出设计

## 目标

当登录用户角色严格为“行政经理”时，员工管理“下载部门明细”生成一个加密 ZIP，包含四个公司部门明细 Excel 和一个集团总表：

- `hr_0001`、`hr_0003`、`hr_0004`、`hr_0005` 各自读取本库数据并各生成一个 Excel；
- `hr_0002`（成都公司）不生成明细，也不进入集团总表；
- 明细文件名为“公司名部门明细.xlsx”；
- 总表参考业务模板，但删除“月总伙食成本”和“月伙食成本”，总成本只累加固定薪资、绩效薪资、社保、公积金；
- ZIP 使用密码加密，密码通过 `X-Archive-Password` 响应头返回，前端下载后提示用户。

普通角色继续走当前单租户 Excel 下载逻辑。

## 业务口径

部门明细中的“薪资待遇”按固定薪资、固定绩效、职务补助、其他补助、全勤顺序拼接。全勤金额只有员工 `full_attendance=1` 且不是试用期时才追加；`full_attendance=2` 不追加。历史的全勤金额为 `100` 时不追加特殊规则继续保留。部门成本不因跨公司导出而改变既有员工范围和金额来源。

公司名从目标租户库的顶层组织读取，不能使用当前登录租户的公司名替代其它租户。每个租户切换前保存当前 `CompanyContext`，查询和写 Excel 完成后在 `finally` 中恢复，避免污染请求线程。

## 组件与数据流

后端保留现有 `EmployeeDepartmentDetailExportSupport` 作为单公司工作簿生成器，新增跨公司编排器负责：

1. 判断角色；
2. 为每个白名单公司切换数据源上下文；
3. 查询该库员工、动态字段、薪资档案、社保公积金、顶层组织；
4. 生成“公司名部门明细.xlsx”字节；
5. 按模板结构生成集团总表；
6. 使用 Zip4j 生成 AES 加密 ZIP，并返回 ZIP 文件名和密码响应头。

集团总表通过四个公司级汇总对象生成，不重新读取成都数据，不写伙食相关列。压缩包内所有文件均为真实 `.xlsx` 文件，不能只返回单个公司工作簿或普通未加密 ZIP。

## 接口与前端

后端仍使用 `/hrmEmployee/exportDepartmentDetail`，根据登录角色决定返回 `.xlsx` 或 `.zip`。ZIP 返回 `Content-Disposition` 和 `X-Archive-Password`；跨域过滤器暴露这两个响应头。

前端 Axios 对 Blob 下载保留响应头，下载工具优先解析 `Content-Disposition` 文件名，触发 ZIP 下载后用中文消息提示密码，并提供一键复制按钮。旧页面的 `res?.data || res` 兼容逻辑继续有效，普通 Excel 下载不要求读取密码。

## 测试策略

- 全勤支持类测试覆盖 `full_attendance=1/2`、试用期和历史 `100` 规则；
- Mapper XML 测试确认返回 `fullAttendance`；
- 后端编排测试覆盖角色白名单、排除 `hr_0002`、公司上下文恢复、总表删除伙食列；
- ZIP 集成级支持测试检查五个文件、文件名、总表内容和 Zip4j 密码校验；
- 控制器/跨域测试确认密码和下载文件名响应头；
- 前端源码测试确认 Blob 响应头保留、ZIP 文件名解析和密码提示。

## 错误处理

任一目标租户查询或工作簿生成失败时，接口返回中文业务错误，不生成不完整 ZIP。上下文恢复放在 `finally`，即使切库或压缩失败也恢复原登录租户。前端下载失败时释放 loading 并显示后端中文消息或“下载部门明细失败”。
