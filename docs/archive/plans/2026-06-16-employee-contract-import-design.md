# 员工合同导入设计

## 背景

员工管理需要新增“导入合同”能力，业务模板位于 `/Users/jiangyongming/Desktop/农谷导入数据/合同导入模版.xlsx`。模板首行为字段，每一行表示一份合同；同一员工可以有多份合同。为避免同名员工合同写错，导入时必须使用“姓名 + 电话”共同匹配员工。

## 推荐方案

- 后端新增独立的合同导入接口 `/hrmEmployeeContract/import`，不复用员工花名册 `/hrmEmployee/import`，避免混入员工主信息、动态字段和其它子表导入语义。
- 合同服务读取当前激活的可见工作表，按表头解析“姓名、电话、合同编号、合同类型、合同开始日期、合同结束日期、合同状态、签约公司、合同签订日期、合同备注”。
- 导入前构建未删除员工的 `姓名 + 归一化手机号` 索引；找不到员工或系统内存在重复键时抛出中文业务错误并整体回滚。
- 每个非空数据行都构造一条 `HrmEmployeeContract`，显式清空 `contractId` 后复用 `addOrUpdateContract(...)`，保持合同期限自动计算和新增行为记录逻辑一致。
- 前端员工管理工具栏新增常驻“导入合同”按钮，使用独立 loading 状态，上传后检查 `code=0` 再提示成功并刷新列表。

## 备选方案

- 复用员工花名册导入链路：实现快，但花名册导入承担员工主表、动态字段和多类子表保存，合同模板错误提示不清晰，且容易误触发员工资料更新；不采用。
- 前端逐行调用现有添加合同接口：无需新增后端解析接口，但网络请求多、不能整体事务回滚，且前端承担员工匹配风险；不采用。

## 验证

- 后端单测覆盖同名员工按电话匹配、一人多合同逐行新增、合同类型/状态中文枚举解析、导入主键清空。
- 前端静态测试覆盖 API 地址、multipart 请求头、按钮文案、loading/disabled、业务码校验、错误提示和成功提示顺序。
