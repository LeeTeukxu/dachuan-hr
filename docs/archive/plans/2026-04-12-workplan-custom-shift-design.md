# 添加排班自定义班次设计

> 已被 2026-04-12 最新业务变更替代：当前自定义班次不再同步到钉钉，只保存到本地库并复用本地相同时间班次。以下内容保留作历史设计记录。

## 背景
- 现有 `/workPlan/saveAll` 仅支持标准班次 `classId` 排班，无法直接表达“08:30-17:30”这类自定义时间。
- 钉钉排班接口 `topapi/attendance/group/schedule/async` 只能提交 `shiftId`，不能直接提交自定义开始/结束时间。
- 新需求要求自定义班次真正影响钉钉考勤，且支持同一行多员工、跨多个考勤组。

## 已确认业务规则
- 自定义班次只支持单段上下班时间。
- 时间格式为严格 `HH:mm`，允许任意分钟。
- `customEnd <= customStart` 视为跨天，前端展示“次日下班”。
- 同一行允许多员工，多员工可以分属不同考勤组。
- 若自定义时间与现有标准班次完全一致，直接复用标准班次。
- 系统生成的自定义班次长期保留，不做自动清理。
- 标准班次与自定义班次的最终提交结果以钉钉成功为准。

## 后端方案
- `/workPlan/saveAll` 保留原路径，但语义调整为“创建排班提交任务并返回 `taskId`”。
- 后端异步将每一行按员工拆分为最小执行单元。
- 自定义班次执行链路：
  1. 解析员工所属考勤组。
  2. 先查 Redis 热缓存。
  3. 未命中则查自定义班次映射表。
  4. 仍未命中则查钉钉现有班次；完全命中标准班次时直接复用。
  5. 仍未命中则创建钉钉班次。
  6. 若考勤组尚未可用该班次，则更新考勤组班次列表。
  7. 最后调用钉钉排班接口提交。

## 缓存与持久化
- 增加自定义班次映射表，唯一键为 `corpId + groupId + start + end + crossDay`。
- Redis 作为热缓存，本地表作为长效事实表。
- `attendanceData/getGoupList`、`attendanceData/getAllShifts` 增加 `10` 分钟展示缓存。
- 系统新增或挂载班次后，主动失效相关缓存。

## 失败与重试
- 提交任务由后端自动重试，最多 `10` 次。
- 前端仅轮询任务进度，不重复调用提交接口。
- `10` 次后仍失败则整次失败。
- 失败结果按“行 x 员工”维度返回，至少包含行号、员工、考勤组、班次或时间段、中文错误原因。
- 面向用户的错误文案使用业务语言，不透出英文或技术术语。

## 前端落点
- `hr_web/src/views/hrm/attendance/records/components/AddOrEdit.vue`
  - 新增 `班次类型` 列；
  - `标准班次` 继续走现有下拉；
  - `自定义班次` 显示 `开始时间 / 结束时间` 输入框；
  - 提交后轮询任务进度，失败按行标红展示中文错误。
- `hr_web/src/api/hrm/attendance/workPlan.js`
  - `saveWorkPlanAll` 改为任务化提交；
  - 新增排班提交进度查询接口。
