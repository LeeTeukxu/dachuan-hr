# 钉钉接口及数据库

## 适用范围

- 本文仅覆盖同步考勤入口 `/attendanceData/sync` 与 `/attendanceData/syncAll`。
- 对应主链路为 `HrmAttendanceDataController -> HrmAttendanceDataServiceImpl#SyncDataWithResume`。
- 本文只整理“同步考勤主流程直接调用的钉钉接口”和“这些接口数据直接写入的本地表”。
- 不包含其他独立定时任务或辅助接口，例如 `AttendanceEmpScheduleTask`、`AttendanceRecordManager`。

## 分步骤说明

### 1. 同步考勤组和班次

调用接口：

- `topapi/attendance/getsimplegroups`：拉取钉钉考勤组列表、考勤组类型、默认标记、班次摘要、部门名称列表。
- `topapi/attendance/shift/query`：按班次 ID 查询详细班次时段，用于补全上下班时间、最早最晚打卡时间、休息时段等。

直接落库：

- `hrm_attendance_group`：保存考勤组主数据，同时把当前已挂载班次 ID 组装到 `shift_setting`。
- `hrm_attendance_group_relation_dept`：保存考勤组与本地部门的对应关系。
- `hrm_attendance_group_relation_employee`：根据部门下员工生成考勤组与员工的关系快照。
- `hrm_attendance_shift`：保存当前考勤组下班次的完整时间配置。

说明：

- 这一阶段先完整拉取远端快照，再统一替换本地快照，避免接口失败时把本地考勤组和班次表清成半套数据。

### 2. 同步考勤用户映射

调用接口：

- `topapi/smartwork/hrm/employee/queryonjob`：分页获取在职员工的钉钉用户 ID。
- `queryDismissionStaffIdList`：分页获取离职员工的钉钉用户 ID。
- `topapi/smartwork/hrm/employee/v2/list`：根据一批用户 ID 拉取花名册详情，提取姓名、手机号等字段。
- `topapi/attendance/getusergroup`：当本地没有员工与考勤组关系时，兜底查询员工当前所属考勤组。

直接落库：

- `tbattendanceuser`：保存钉钉 `userId` 与本地 `empId` 的映射，以及姓名、部门、考勤组等信息。

说明：

- 该步骤是后续排班计划、打卡明细、报表数据按员工写库的基础映射。
- `getusergroup` 不是每次必调，只有本地关系表无法给出考勤组时才会调用。

### 3. 同步考勤计划

调用接口：

- `topapi/attendance/listschedule`：按日期拉取员工排班计划。

直接落库：

- `hrm_attendance_plan`：保存计划 ID、员工 ID、钉钉用户 ID、考勤组 ID、班次 ID、班次配置 ID、计划打卡时间、打卡类型、工作日期等。

说明：

- 当前实现会按员工和日期范围删除旧计划后重写，保证目标日期内是最新计划快照。

### 4. 同步打卡明细

调用接口：

- `attendance/listRecord`：按员工批量查询指定时间范围内的打卡记录。

直接落库：

- `hrm_attendance_clock`：保存业务侧直接使用的打卡明细，如上下班类型、打卡状态、打卡方式、打卡阶段、位置等。
- `tbattendancedetail`：保存钉钉原始打卡记录镜像，便于后续问题排查和兜底取数。

说明：

- `hrm_attendance_clock` 偏业务化；
- `tbattendancedetail` 更接近钉钉返回原始结构。

### 5. 同步考勤报表字段

调用接口：

- `topapi/attendance/getattcolumns`：拉取考勤报表字段定义。

直接落库：

- `hrm_attendance_report_field`：保存字段 ID、字段名称、字段类型（普通日报字段/请假字段）。

说明：

- 该表是步骤 7 查询字段值时的字段字典。

### 6. 清理旧报表数据

调用接口：

- 本步骤不新增调用钉钉接口。

直接落库：

- `hrm_attendance_report_data`：删除当前同步员工、当前日期区间内的旧报表数据。

说明：

- 这是报表数据回灌前的清理步骤，本身不拉取新数据，但属于同步考勤主流程的一部分。

### 7. 回灌报表数据

#### 7a. 同步日报类字段

调用接口：

- `topapi/attendance/getcolumnval`：按员工、按时间范围查询考勤日报字段值，例如出勤、加班等字段。

直接落库：

- `hrm_attendance_report_data`：保存字段 ID、字段名称、员工 ID、日期、字段值。

#### 7b. 同步请假类字段

调用接口：

- `topapi/attendance/getleavetimebynames`：按员工、按时间范围查询请假类字段时长。

直接落库：

- `hrm_attendance_report_data`：保存请假字段值，和日报类字段共用同一张明细表。

说明：

- 步骤 7a 和 7b 最终都写入 `hrm_attendance_report_data`，只是字段来源不同。

## 本同步功能未直接写入的表

以下表与考勤相关，但不是 `/attendanceData/sync`、`/attendanceData/syncAll` 这两个同步入口直接写入的结果：

- `hrm_attendance_date_shift`：由考勤组配置/生效链路生成，不是本同步接口直接写入。
- `hrm_emp_schedule`：由独立定时任务 `AttendanceEmpScheduleTask` 调 `schedule/listbyusers` 写入，不属于本同步入口。
- `hrm_attendance_history_shift`：来自班次维护链路，不是本同步入口直接写入。
