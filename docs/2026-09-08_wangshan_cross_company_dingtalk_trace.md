# 数据排查记录：湖北农谷同步未匹配清单出现「王山」（其档案本属达川）

> 记录日期：2026-09-08
> 关联功能：组织管理-同步钉钉数据 → 同步部门后同步员工部门（`hrm_employee.dept_id`）
> 处理性质：**数据/钉钉通讯录归属问题**，非代码 bug。本文档供反馈湖北农谷钉钉管理员清理使用。

---

## 一、现象

湖北农谷（租户 `hr_0003` / companyId `0003`）执行「同步员工部门」后，未匹配清单上报 3 人（王山 / 谷鹏 / 罗毅龙），其中王山本人档案明确属于达川公司（租户 `hr_0001`），疑为同步误判。

## 二、结论（一句话）

**王山是同一自然人（同手机号、同钉钉号），达川为有效档案；湖北农谷自己的钉钉组织里残留了他的账号，仍挂在「湖北田野农谷生物科技有限公司_行政人力资源部」；湖北系统里对应档案已删除（`is_del=1`）且未绑钉钉，同步在"未删除员工"范围内匹配不到 → 判未匹配。**

同步逻辑本身正确；需处理的是**湖北农谷钉钉通讯录中残留的达川王山账号**。

## 三、取证数据

同一个人标识：手机号 `18689834841`；钉钉 userid `1700214343940614`；钉钉 unionid `FLUYlRdp7iSwDriPgpiSiSpvQgiEiE`。

FROM hrm_employee WHERE mobile = '18689834841';

### 2. 湖北农谷 `hr_0003` —— 王山档案已被删除、未绑钉钉

> 湖北库中不存在绑定钉钉号 `1700214343940614` 的档案；该手机号在湖北库仅此一条（且为已删除）。

### 3. 湖北农谷自己的钉钉组织 —— 该账号仍存在并挂部门

用湖北钉钉内部应用凭证（`hrsystem.ddaccount`，companyId=0003）换取 access_token 后实时校验：

- `topapi/v2/user/getbymobile`，mobile=`18689834841` → 返回 userid `1700214343940614`
- `topapi/v2/user/get`，userid=`1700214343940614` → 结果：
  - `name`：王山
  - `mobile`：18689834841
  - `active`：true
  - `dept_id_list`：`[68912184]` → 部门「**湖北田野农谷生物科技有限公司_行政人力资源部**」，该钉钉部门共 8 人（王山为其一）

## 四、成因推断

王山曾同时在达川 / 湖北系统建档（两处手机号一致）。后续湖北侧档案被删除（`is_del=1`），但**湖北农谷钉钉组织未同步移除/停用该账号**，导致其仍存活于湖北钉钉通讯录。湖北租户每次同步会扫到它，而本地有效档案查无此人 → 稳定出现在未匹配清单。

## 五、处置建议（需湖北农谷钉钉管理员操作）

1. 到**湖北农谷的钉钉管理后台**，将 userid `1700214343940614`（王山，手机号 18689834841）从「行政人力资源部」/组织中**移除或停用**（若他确只归属达川）。
2. 移除后湖北租户下次同步即不再扫到王山，未匹配清单恢复正常。
3. 湖北本地系统那条 `is_del=1` 的王山档案为已删除数据，**无需处理**。

## 六、复核方法

同步前/后可在湖北租户执行一次「同步钉钉数据」查看未匹配清单是否仍含王山；或直接按第三节 SQL 与钉钉接口复查账号状态。
