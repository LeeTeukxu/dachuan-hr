## 修复方案：跨月请假单（调休/年假）按月拆分显示

### 根因
- `HrmAttendanceApprovalProcessInstanceParser.resolveDateRange`（`HrmAttendanceApprovalProcessInstanceParser.java:220-245`）找开始/结束时间只认组件名"开始时间/开始日期/加班…/出差…/补卡时间"；钉钉请假控件名（如"请假时间"）不匹配 → `beginTime` 兜底为发起时间(7/24)、`endTime` 兜底为审批完成时间(7月内) → 落库区间全在 7 月 → 8 月列表查不到。
- 列表 XML（`HrmAttendanceApprovalMapper.xml:68-73`）的区间交集判定本身已正确，但被脏数据架空。

### 改动（仅"入库 + 显示"，统计口径不动）

**1. 解析修复（Parser）**
- 请假类组件名候选加入："请假时间"、"请假开始/结束时间"、"假期"等；
- 优先从请假控件 `ext_value` 读权威 `start_time`/`end_time`（毫秒，与时长解析同源）；
- 最后兜底：命名均未命中时，扫描全部组件 value 文本中的日期，取 min/max 作为业务区间；
- `ParserTest` 补用例：请假时间组件 + ext_value 场景的跨月单（7/24~8/4）解析出正确 beginTime/endTime。

**2. 存量数据修复**
- 改完后对该员工重新"获取审批数据"（幂等重拉覆盖脏行）；如重拉不覆盖则出一条 SQL 修正脚本放 `docs/sql/`。

**3. 列表按月拆分显示（Java 层，不改表、不改统计）**
- `HrmAttendanceApprovalServiceImpl#queryPageList` 查询后处理：与所选月相交的记录，把展示的 `beginTime/endTime` 截断为 `[max(begin,月初), min(end,月末)]`，时长按自然天数占比折算（该月天数/总天数 × 总小时，取 0.5h 粒度）；
- 7 月显示 7/24~7/31 部分、8 月显示 8/1~8/4 部分，各自时长为该月部分；数据库仍存一条完整记录，统计/其他模块不受影响。

**4. 诊断与验证**
- 实现第一步先直查租户库该调休单的 `beginTime/endTime/workDate` 确认根因（需 mysql 只读权限）；
- `mvn compile` + ParserTest 全绿；按验收口径自测：7 月、8 月各自显示正确区间与时长。

**5. 文档收尾**
- 更新 `docs/modules/attendance-sync.md` 近期变更（替换 2026-09-05 的 L1 条目，记录解析根因与拆分显示方案）。

不涉及表结构、接口契约、小程序契约变更。
